# R1: Vendor extraction and a device tree without Google files — Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the owner's factory image fills `vendor/glass/glass-1/` with the binaries the build needs, and `OpenMyGlass/android_device_glass_glass-1` has its own `rootdir/` and `system.prop` again, written from a facts document instead of Google's files.

**Architecture:**
- glass-rom (GPL-3.0) gets `tools/extract_vendor.py`. It reads a list of files, dumps them from the raw system image with `debugfs`, and writes `device-vendor.mk`.
- The device tree (Apache-2.0) only holds the list and the makefiles, and never imports glass-rom code: the owner runs the tool as a separate program.
- `rootdir/` is rebuilt clean-room. Task 5 writes `docs/hardware-facts.md` from the stock files. Task 6 writes the new files from that document only.

**Tech stack:** Python 3 standard library, `debugfs`/`mke2fs` from e2fsprogs, GitHub Actions, shellcheck.

**Spec:** [`2026-10-21-open-source-roadmap.md`](2026-10-21-open-source-roadmap.md), phase R1.

## Global constraints

- No Google file, and nothing extracted from one, is committed to any repo, test fixture or CI artifact. Facts (paths, modes, partition names, property values) may be written down.
- glass-rom code: GPL-3.0, Python stdlib only, tests with `unittest` in `tests/`, run by `python3 -m unittest discover -s tests -t tests -v`.
- Device tree: Apache-2.0. Every new file starts with `SPDX-License-Identifier: Apache-2.0` in that file's comment syntax. Work branches off `android-6.0.1_r31` and lands through pull requests, because the default branch is protected.
- Device paths are `device/glass/glass-1/…` and vendor paths are `vendor/glass/glass-1/…`, as the existing makefiles use.
- English in all repo content.

## Review focus

1. A list entry missing from the image: the tool must name every missing path and write nothing, not leave a half-filled vendor directory (Task 2, `test_missing_files_are_all_reported`).
2. Running the tool twice into the same directory must give the same result, not duplicated makefile lines (Task 2, `test_rerun_is_identical`).
3. A list line with trailing spaces or Windows line endings must parse like a clean one (Task 1, `test_whitespace_and_crlf`).
4. A `PRODUCT_COPY_FILES` source that points at a file removed from the tree must fail the tree check (Task 4, `test_missing_copy_source`).
5. A binary file added to the device tree by mistake must fail the tree check (Task 4, `test_binary_file_rejected`).

### Task 1: List parsing and makefile generation (glass-rom)

**Files:**
- Create: `tools/extract_vendor.py`
- Test: `tests/test_extract_vendor.py`

**Interfaces:**
- Produces:
  - `parse_list(text: str) -> list[tuple[str, str]]` returns `(src, dst)` pairs.
    - `src` and `dst` are paths relative to `/system`, with no leading slash.
    - A line is `path` or `src:dst`. `#` starts a comment, and blank lines are skipped.
    - Raises `ExtractError` for an absolute path, a `..` component, or a duplicate `dst`.
  - `vendor_makefile(entries: list[tuple[str, str]], vendor_dir: str = "vendor/glass/glass-1") -> str`.
  - `class ExtractError(Exception)`.

- [ ] **Step 1: Write the failing tests** in `tests/test_extract_vendor.py`:
  - `test_plain_and_renamed`: `parse_list("lib/a.so\nvendor/x.bin:vendor/firmware/x.bin\n")` returns `[("lib/a.so", "lib/a.so"), ("vendor/x.bin", "vendor/firmware/x.bin")]`.
  - `test_comments_and_blanks`: `"# c\n\nlib/a.so # tail\n"` returns `[("lib/a.so", "lib/a.so")]`.
  - `test_whitespace_and_crlf`: `"  lib/a.so  \r\n"` returns `[("lib/a.so", "lib/a.so")]`.
  - `test_rejects_bad_paths`: each of `/lib/a.so`, `lib/../a.so` and two lines with the same `dst` raises `ExtractError`.
  - `test_makefile`: for `[("lib/b.so", "lib/b.so"), ("etc/a.conf", "etc/a.conf")]`, `vendor_makefile` returns exactly:
    ```
    # Generated by glass-rom tools/extract_vendor.py from the owner's factory image. Do not commit.
    PRODUCT_COPY_FILES += \
        vendor/glass/glass-1/proprietary/etc/a.conf:system/etc/a.conf \
        vendor/glass/glass-1/proprietary/lib/b.so:system/lib/b.so
    ```
    That is, sorted by `dst`, four-space indent, and no backslash on the last line.
- [ ] **Step 2: Run** `python3 -m unittest tests.test_extract_vendor -v` from `tests/`'s parent. Expected: an `ImportError` / FAIL.
- [ ] **Step 3: Implement** `parse_list`, `vendor_makefile` and `ExtractError` in `tools/extract_vendor.py`. The module docstring's first line is `Extract the binaries a Glass build needs from the owner's raw system image.`
- [ ] **Step 4: Run the tests.** Expected: PASS.
